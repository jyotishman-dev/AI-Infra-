# 1. What Are Embeddings?

An embedding is a numerical representation of text, images, audio, or other data in the form of a vector (an array of numbers).

LLMs and machine learning systems cannot directly perform mathematical similarity calculations on ordinary text. Embeddings convert information into numerical vectors so that computers can compare semantic meaning.

### Example

Original text:

```text
"TypeScript adds static typing to JavaScript."
```

A simplified embedding might look like:

```ts
[0.21, 0.83, -0.42, 0.65, 0.19]
```

**Note:** These are illustrative numbers, not actual Gemini embeddings.

### Why do we need embeddings?

- Semantic search
- Recommendation systems
- Document retrieval
- RAG applications
- Duplicate detection
- Similarity matching
- Clustering related information

### Important concept

Similar meanings should generally produce vectors that are close in the embedding space, even when the actual words are different.

Example:

```text
"How can I validate JSON?"
"How do I check whether data follows a schema?"
```

These sentences have different words but similar meanings.

A good embedding model should capture this relationship.

# 2. What Is a Vector?

A vector is an ordered collection of numerical values.

Example:

```ts
const vector = [0.2, 0.5, 0.8, 0.1];
```

This vector has 4 dimensions.

Real embedding models can generate vectors with hundreds or thousands of dimensions.

For example, an embedding model might return:

```ts
[
  0.023,
  -0.124,
  0.543,
  0.891,
  // ... many more values
]
```

### What are dimensions?

Dimensions represent the numerical space in which the embedding model represents information.

We should not interpret each dimension as one specific human-readable feature.

The model learns a representation in which semantic relationships can be captured through vector comparisons.

# 3. Mock Embeddings vs Real Embeddings

In our first implementation, we used a mock embedding function.

### Mock Embedding

```ts
function getMockEmbedding(text: string): number[] {
  let hash = 0;

  for (let i = 0; i < text.length; i++) {
    hash = (hash << 5) - hash + text.charCodeAt(i);
    hash |= 0;
  }

  return [
    Math.sin(hash) * 10,
    Math.cos(hash) * 10,
    Math.sin(hash * 2) * 10,
    Math.cos(hash * 2) * 10
  ];
}
```

This function generates deterministic numerical values using a text hash.

However, it does not understand the meaning of the text.

### Real Embeddings

A real embedding model learns semantic representations from training data.

For example:

```text
"Redis is used for caching."
"Redis stores data in memory."
```

A semantic embedding model can recognize that these sentences are related.

| Mock Embeddings | Real Embeddings |
|---|---|
| Generated using mathematical operations | Generated by an embedding model |
| No semantic understanding | Captures semantic relationships |
| Useful for testing code structure | Useful for actual semantic search |
| Not suitable for meaningful retrieval | Suitable for semantic retrieval |

**Takeaway:** Mock embeddings help us test the implementation. Real embeddings make semantic search possible.

# 4. Gemini Embeddings API

Google Gemini provides an embedding API that converts text into numerical vectors.

We use the `@google/genai` SDK.

### Installation

```bash
bun add @google/genai
```

### Environment Variable

Create a `.env` file:

```env
GEMINI_API_KEY=your_api_key
```

Never expose your API key in public repositories.

### Initialize Gemini

```ts
import { GoogleGenAI } from "@google/genai";

const ai = new GoogleGenAI({
  apiKey: process.env.GEMINI_API_KEY!
});
```

### Generate an Embedding

```ts
async function getEmbedding(text: string): Promise<number[]> {

  const response = await ai.models.embedContent({
    model: "gemini-embedding-2",
    contents: text
  });

  const vector = response.embeddings?.[0]?.values;

  if (!vector) {
    throw new Error("Embedding generation failed");
  }

  return vector;
}
```

### What happens internally?

1. We provide text to Gemini.
2. Gemini processes the text using its embedding model.
3. The model generates a numerical vector.
4. The API returns the embedding.
5. We store the vector for future similarity comparisons.

# 5. What Is Semantic Search?

Semantic search retrieves information based on meaning rather than simply matching exact keywords.

### Traditional Keyword Search

Query:

```text
"Fast caching"
```

A keyword search looks for matching words such as "fast" and "caching".

### Semantic Search

Query:

```text
"What technology stores data in memory for quick access?"
```

A semantic search system can retrieve:

```text
"Redis is an in-memory data structure store used for caching."
```

Even though the sentences don't use exactly the same words.

### Why is semantic search useful?

- Search engines
- AI chatbots
- Knowledge management systems
- Customer support applications
- Document search
- Enterprise AI assistants

# 6. Cosine Similarity

Cosine similarity is a mathematical technique used to measure how similar two vectors are based on the angle between them.

It is widely used in semantic search and vector databases.

### Formula

\[
\text{Cosine Similarity}(A,B)
=
\frac{A \cdot B}{||A|| \times ||B||}
\]

Where:

- A = First vector
- B = Second vector
- A · B = Dot product
- ||A|| = Magnitude of vector A
- ||B|| = Magnitude of vector B

### Understanding the result

| Score | General interpretation |
|---|---|
| Close to +1 | Vectors point in similar directions |
| Around 0 | Vectors are approximately perpendicular |
| Close to -1 | Vectors point in opposite directions |

The exact interpretation depends on the embedding model and dataset.

### TypeScript Implementation

```ts
function cosineSimilarity(
  vecA: number[],
  vecB: number[]
): number {

  if (vecA.length !== vecB.length) {
    throw new Error("Vector dimensions do not match");
  }

  let dotProduct = 0;
  let magA = 0;
  let magB = 0;

  for (let i = 0; i < vecA.length; i++) {

    dotProduct += vecA[i] * vecB[i];

    magA += vecA[i] ** 2;

    magB += vecB[i] ** 2;
  }

  const denominator = Math.sqrt(magA) * Math.sqrt(magB);

  if (denominator === 0) return 0;

  return dotProduct / denominator;
}
```

### Understanding the code

**1. Dot Product**

```ts
dotProduct += vecA[i] * vecB[i];
```

Multiplies corresponding elements of both vectors and adds their products.

**2. Magnitude**

```ts
magA += vecA[i] ** 2;
magB += vecB[i] ** 2;
```

Calculates the sum of squared values.

**3. Final Calculation**

```ts
return dotProduct / denominator;
```

Divides the dot product by the product of both vector magnitudes.

# 7. Building a Semantic Search System

Our implementation has two main components:

### A. Knowledge Base

A knowledge base contains the information we want to search.

Example:

```ts
const sentences = [
  "TypeScript adds static typing to JavaScript.",
  "Zod validates data schemas at runtime.",
  "PostgreSQL is a relational database.",
  "Redis is an in-memory data structure store.",
  "WebSockets allow real-time communication."
];
```

We generate embeddings for all sentences.

```ts
const sentenceEmbeddings = await Promise.all(
  sentences.map(async (text) => ({
    text,
    vector: await getEmbedding(text)
  }))
);
```

Now every sentence has:

- Original text
- Its numerical embedding

### B. Query Embedding

When a user asks a question:

```ts
const query = "How can I validate JSON data?";
```

We generate another embedding:

```ts
const queryVector = await getEmbedding(query);
```

Then compare it against all stored sentence embeddings.

### C. Find the Closest Match

```ts
function findClosestSentence(
  queryVector: number[],
  sentenceEmbeddings: {
    text: string;
    vector: number[];
  }[]
) {

  const results = sentenceEmbeddings.map(item => ({
    text: item.text,
    score: cosineSimilarity(queryVector, item.vector)
  }));

  results.sort((a, b) => b.score - a.score);

  return results;
}
```

The highest-scoring result is returned first.

# 8. What Is Top-K Retrieval?

Instead of returning only one matching document, we can retrieve multiple relevant documents.

K represents the number of results we want.

Example:

```ts
const topK = 3;

const results = await findClosestSentence(
  queryVector,
  sentenceEmbeddings
);

const topResults = results.slice(0, topK);
```

If K = 3, the system returns the three highest-scoring matches.

### Why Top-K?

A single document might not contain enough information to answer a question.

Retrieving multiple documents gives the LLM more relevant context.

# 9. What Is a Vector Database?

A vector database is a database designed to store and retrieve vector embeddings efficiently.

Instead of calculating similarity against every vector manually, a vector database provides indexing and search capabilities.

### Popular Vector Database Options

| Technology | Purpose |
|---|---|
| pgvector | Vector search extension for PostgreSQL |
| Pinecone | Managed vector database |
| Qdrant | Vector search engine |
| Weaviate | Vector database |
| Milvus | Large-scale vector database |

### Why pgvector?

If we already use PostgreSQL, pgvector allows us to store normal application data and embeddings in the same database.

Example:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE documents (
  id SERIAL PRIMARY KEY,
  content TEXT,
  embedding VECTOR(768)
);
```

Note: The vector dimension must match the actual embedding output. The value `768` here is illustrative, not a guaranteed dimension for every Gemini embedding model.

### Similarity Search

```sql
SELECT
  content,
  1 - (embedding <=> '[0.1, 0.2, 0.3]') AS similarity
FROM documents
ORDER BY embedding <=> '[0.1, 0.2, 0.3]'
LIMIT 3;
```

Here:

- `<=>` represents cosine distance in pgvector.
- Smaller distance means greater similarity.
- `1 - distance` gives cosine similarity for normalized vectors.

The example vector must be replaced with a real vector of the table's configured dimensions.

# 10. What Is RAG?

RAG stands for Retrieval-Augmented Generation.

It is an architecture that combines information retrieval with text generation.

Instead of relying only on the LLM's internal knowledge, we retrieve relevant information from an external knowledge base and provide it as context.

### Why RAG?

LLMs have limitations:

- They may generate incorrect information.
- They may not know private company information.
- Their training knowledge may be outdated.
- They cannot automatically access our private database.

RAG helps address these limitations by retrieving relevant external information.

### RAG Architecture

```text
             DOCUMENTS
                 |
                 v
          Document Chunking
                 |
                 v
         Gemini Embeddings
                 |
                 v
          Vector Database
                 |
                 |
USER QUERY ------+
                 |
                 v
         Query Embedding
                 |
                 v
          Vector Search
                 |
                 v
         Top-K Retrieval
                 |
                 v
       Retrieved Documents
                 |
                 v
          LLM + Context
                 |
                 v
          Final Answer
```

### Two Main Phases

**Phase 1: Indexing**

1. Collect documents.
2. Split documents into chunks.
3. Generate embeddings.
4. Store embeddings in a vector database.

**Phase 2: Retrieval and Generation**

1. Receive the user's query.
2. Generate the query embedding.
3. Retrieve relevant chunks.
4. Pass retrieved chunks and the question to the LLM.
5. Generate the final answer.

# 11. What Is Document Chunking?

Document chunking means dividing large documents into smaller pieces before generating embeddings.

Example:

A 100-page PDF can be divided into multiple smaller text chunks.

```text
Document
   |
   +---- Chunk 1
   |
   +---- Chunk 2
   |
   +---- Chunk 3
   |
   +---- Chunk 4
```

Each chunk gets its own embedding.

### Why chunking?

- Better retrieval accuracy.
- More manageable context.
- Avoids sending entire documents to the LLM.
- Makes it easier to retrieve specific information.

### Overlapping Chunks

Sometimes we use overlapping chunks to preserve context between neighboring sections.

For example:

```text
Chunk 1: Words 1–100
Chunk 2: Words 80–180
Chunk 3: Words 160–260
```

The overlap helps prevent important information from being lost at chunk boundaries.

# 13. Important Engineering Considerations

When moving from a learning example to production:

1. Generate document embeddings once and reuse them.
2. Cache or persist embeddings instead of regenerating them.
3. Use the same compatible embedding model for documents and queries.
4. Ensure vector dimensions match.
5. Handle API errors and rate limits.
6. Use batching when supported.
7. Consider vector indexing for large datasets.
8. Retrieve more than one document when necessary.
9. Evaluate retrieval quality using real queries.
10. Do not assume the highest similarity score guarantees a correct answer.
